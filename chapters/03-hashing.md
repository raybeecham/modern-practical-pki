# Chapter 3: Hashing

[Back to README](../README.md)

## Goal

Understand what a hash is, why hashes are useful, and how to generate hashes
with OpenSSL.

A hash is a fixed-length value that represents data. The input can be tiny or
huge, but the hash output has a fixed size for the algorithm being used. The
hash is often encoded as text, usually hexadecimal.

## Hash Functions

A hash is generated by an algorithm called a hash function.

A very simple hash function is:

```text
h(n) = n mod 10
```

This returns the remainder after dividing `n` by 10. The output will always be
between `0` and `9`.

Examples:

```text
h(1)  = 1
h(11) = 1
h(21) = 1
h(31) = 1
```

This shows a collision. A collision happens when two different inputs produce
the same hash output.

Another simple hash function could add up the integer values of each 4-byte
chunk of data and return the total. That gives a much larger range of possible
hash values, up to about `2^32`, but it is still easy to create collisions.

Simple hash functions are useful for learning, but they are not secure.

## Secure Hash Functions

For a hash function to be considered cryptographically secure, it should be
computationally infeasible to:

- Reverse a hash to recover the original input.
- Given a hash, find another input that produces the same hash.
- Find any two different inputs that produce the same hash.

These properties are usually described as:

- Preimage resistance: hard to recover the input from the hash.
- Second preimage resistance: hard to find another input with the same hash.
- Collision resistance: hard to find any two inputs with the same hash.

Examples of cryptographic hash families include SHA-2 and SHA-3.

SHA-2 includes:

- SHA-224
- SHA-256
- SHA-384
- SHA-512

SHA-3 includes:

- SHA3-224
- SHA3-256
- SHA3-384
- SHA3-512

The number in the name is the output size in bits. For example, SHA-256 produces
a 256-bit hash.

## Hashing Passwords

Hashing can help authenticate users without storing their original passwords.
When a user registers, the system stores a password hash instead of the password
itself. Later, when the user logs in, the system hashes the submitted password
and compares it to the stored hash.

Important real-world note: production password storage should not use plain,
fast hash functions like SHA-256 by themselves. Real systems use salts and
password-hashing algorithms such as Argon2, bcrypt, scrypt, or PBKDF2. Those are
designed to slow down guessing attacks.

For this chapter, we are focused on the basic hash idea.

## Try It

Run these inside the container, not from the `PS F:\...>` PowerShell prompt:

```bash
mkdir -p lab/chapter3
echo -n "Hello World" > lab/chapter3/message.txt
openssl dgst -sha256 lab/chapter3/message.txt
```

Expected output:

```text
SHA2-256(lab/chapter3/message.txt)= a591a6d40bf420404a011733cfb7b190d62c65bf0bcda32b57b277d9ad9f146e
```

The exact label may vary by OpenSSL version, but the digest should be:

```text
a591a6d40bf420404a011733cfb7b190d62c65bf0bcda32b57b277d9ad9f146e
```

That output has 64 hexadecimal characters. Each hex character represents 4
bits:

```text
64 hex characters * 4 bits = 256 bits
```

That is why SHA-256 hashes are commonly shown as 64 hex characters.

## Small Change, Different Hash

Now change only one letter:

```bash
echo -n "hello World" > lab/chapter3/message-changed.txt
openssl dgst -sha256 lab/chapter3/message-changed.txt
```

Expected output:

```text
SHA2-256(lab/chapter3/message-changed.txt)= db4067cec62c58bf8b2f8982071e77c082da9e00924bf3631f3b024fa54e7d7e
```

The hash will be completely different, even though the text changed only from
uppercase `H` to lowercase `h`.

This is one reason hashes are useful for integrity checks. A tiny change in a
file should produce a very different hash.

## Compare Two Files

Make a copy of the original file:

```bash
cp lab/chapter3/message.txt lab/chapter3/message-copy.txt
openssl dgst -sha256 lab/chapter3/message.txt
openssl dgst -sha256 lab/chapter3/message-copy.txt
cmp lab/chapter3/message.txt lab/chapter3/message-copy.txt && echo "same bytes"
```

Expected result:

```text
same bytes
```

The filenames are different, but the file contents are the same, so the hashes
are the same.

## Try Other Algorithms

OpenSSL supports several digest algorithms:

```bash
openssl dgst -sha224 lab/chapter3/message.txt
openssl dgst -sha256 lab/chapter3/message.txt
openssl dgst -sha384 lab/chapter3/message.txt
openssl dgst -sha512 lab/chapter3/message.txt
openssl dgst -sha3-256 lab/chapter3/message.txt
```

The larger algorithms produce longer digest output.

## HMAC

Hash algorithms can be combined with other algorithms.

HMAC means Hash-based Message Authentication Code. It uses a hash algorithm
along with a secret key to generate a MAC for the data.

Example:

```bash
openssl dgst -sha256 -hmac "secret-key" lab/chapter3/message.txt
```

A plain hash can help detect accidental or unexpected changes. An HMAC can also
prove that someone with the shared secret key generated the value.

## Key Takeaway

Hashing is not encryption. A hash is not meant to be decrypted. A secure hash is
a one-way fingerprint of data that helps with integrity checks, password
verification, signatures, and message authentication.
